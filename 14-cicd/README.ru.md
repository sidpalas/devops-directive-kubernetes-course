# Непрерывная интеграция и непрерывная поставка

> 🌐 [English](README.md) | Русский

CI/CD для Kubernetes можно разбить на несколько составляющих:

1. Сборка образов контейнеров
2. Отправка образов контейнеров в реестр образов
3. Обновление Kubernetes-манифестов новыми тегами образов
4. Применение обновлённых манифестов к кластеру (кластерам)

CI должен также по-прежнему выполнять такие действия, как проверки, линтинг, запуск тестов и т.д., но они не относятся к Kubernetes, поэтому здесь опущены для краткости.

## Эталонная реализация CI

Рабочий GitHub Actions workflow находится в `./github/workflows/image-ci.yml`.

**Примечание:** этот workflow также обновляет теги образов контейнеров в `12-deploying-to-multiple-environments/kluctl` с помощью самодельной и хрупкой подмены строк. Более надёжный подход — использовать https://fluxcd.io/flux/guides/image-update/ или https://docs.renovatebot.com/modules/manager/regex/ для обнаружения новых тегов образов и обновления соответствующих манифестов.

## Поддержание состояния кластера в актуальном виде

Существует множество способов поддерживать развёрнутое состояние Kubernetes-манифестов в актуальном соответствии с конфигурациями в Git.

1. Ручной запуск `kubectl apply` (или аналогичной команды): это работает, но неизбежно кто-то либо забудет запустить команду, либо сделает это в отношении не того кластера.

2. Автоматический запуск `kubectl apply` (или аналогичной команды) из автоматизированного pipeline: это лучше ручного применения, так как исключает человеческую ошибку, однако (A) требуется хранить учётные данные кластера в CI-системе, и (B) дрейф не обнаруживается и не устраняется, если кто-то вручную изменил состояние кластера

3. Автоматическая синхронизация состояния из системы контроля версий («GitOps»): благодаря постоянному получению последних конфигураций и их применению граница безопасности кластера остаётся наиболее прочной, а дрейф обнаруживается и устраняется.

### Реализация GitOps:

Полный пример GitOps (с использованием наших конфигураций из `12-deploying-to-multiple-environments`) с kluctl реализован в `./kluctl-gitops`.

Два других популярных GitOps-инструмента:

- ArgoCD (https://argo-cd.readthedocs.io/en/stable)
- FluxCD (https://fluxcd.io/)
